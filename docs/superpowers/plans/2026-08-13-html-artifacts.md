# Side-by-Side HTML Artifacts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Detect completed HTML code fences and automatically open them in an isolated, resizable workspace beside the chat.

**Architecture:** A pure Markdown fence extractor derives stable artifacts from persisted assistant messages. `ChatMarkdown` exposes preview actions, while `ChatView` owns per-thread selection and a sibling `ArtifactPanel` renders a CSP-injected `iframe.srcdoc` in a sandboxed opaque origin.

**Tech Stack:** TypeScript 5.8, Vitest, React 19, react-markdown 10, Tailwind CSS 4, sandboxed iframe `srcdoc`

## Global Constraints

- Only completed fences labeled `html`, `htm`, or `html_preview` become artifacts.
- The newest completed artifact opens automatically after the assistant message settles.
- Artifact HTML remains canonical in the conversation; do not duplicate it in server persistence.
- The desktop layout is side-by-side and resizable; narrow windows use a full-window preview.
- Artifact documents never receive `allow-same-origin`, Electron APIs, a host bridge, popups, downloads, forms, or top-level navigation.
- The surrounding transcript never renders model HTML with `dangerouslySetInnerHTML`.
- External HTTP(S) assets are allowed and the toolbar indicates network access.
- No push or pull request before the user approves the Electron smoke test.

---

## File Structure

- Create `src/lib/html-artifacts.ts`: complete-fence parsing, stable IDs, and CSP document construction.
- Create `src/lib/html-artifacts.test.ts`: parser and isolation tests.
- Modify `src/components/ChatMarkdown.tsx`: HTML code-block Preview/Reopen action.
- Create `src/components/ArtifactPanel.tsx`: iframe toolbar, refresh, copy, download, close, and responsive UI.
- Modify `src/components/ChatView.tsx`: automatic selection, per-thread restoration, split layout, and resize control.
- Modify `src/styles.css`: range/divider and artifact-specific responsive styles only when Tailwind utilities are insufficient.
- Modify `README.md`: explain artifact detection, automatic opening, and sandbox limitations.

### Task 1: Parse complete HTML artifacts and build isolated documents

**Files:**
- Create: `src/lib/html-artifacts.ts`
- Create: `src/lib/html-artifacts.test.ts`

**Interfaces:**
- Produces: `HtmlArtifact`, `extractHtmlArtifacts(markdown, messageId)`, and `buildArtifactDocument(html)`.
- Consumes: settled assistant Markdown text and the persisted message ID.

- [ ] **Step 1: Write parser and security tests**

Use these assertions:

```ts
expect(extractHtmlArtifacts("```html\n<h1>Hello</h1>\n```", "m1")).toEqual([
  { id: "m1:0", messageId: "m1", index: 0, language: "html", html: "<h1>Hello</h1>" },
]);
expect(extractHtmlArtifacts("```html\n<p>partial", "m1")).toEqual([]);
expect(extractHtmlArtifacts("```js\ndocument.body.innerHTML = 'x'\n```", "m1")).toEqual([]);

const document = buildArtifactDocument("<script>document.body.textContent='ready'</script>");
expect(document).toContain("Content-Security-Policy");
expect(document).toContain("form-action 'none'");
expect(document).not.toContain("allow-same-origin");
```

Also cover tilde fences, four-character fences containing triple backticks, case-insensitive languages, multiple blocks, and an HTML-looking inline snippet that must not match.

- [ ] **Step 2: Run the focused test and verify failure**

Run: `pnpm vitest run src/lib/html-artifacts.test.ts`

Expected: FAIL because the module does not exist.

- [ ] **Step 3: Implement complete-fence extraction**

Implement a line-oriented parser that records the opening character and length, requires a closing fence of the same character with at least the opening length, accepts `html`, `htm`, or `html_preview` case-insensitively, strips only the synthetic terminal newline, and assigns IDs as `${messageId}:${artifactIndex}`.

Export:

```ts
export interface HtmlArtifact {
  id: string;
  messageId: string;
  index: number;
  language: "html" | "htm" | "html_preview";
  html: string;
}
```

- [ ] **Step 4: Implement CSP document construction**

Inject this policy into a full HTML document or wrap fragments with a complete document:

```text
default-src 'none'; img-src data: blob: http: https:; media-src data: blob: http: https:; style-src 'unsafe-inline' http: https:; font-src data: http: https:; script-src 'unsafe-inline' http: https:; connect-src http: https:; form-action 'none'; base-uri 'none'; object-src 'none'; frame-src 'none'
```

Escape only values generated by OpenMausBot; preserve the artifact source byte-for-byte inside the body/document. Add a `<meta name="referrer" content="no-referrer">` and a base stylesheet for margin/color-scheme only when wrapping a fragment.

- [ ] **Step 5: Run parser tests**

Run: `pnpm vitest run src/lib/html-artifacts.test.ts`

Expected: PASS.

- [ ] **Step 6: Commit the artifact core**

```bash
git add src/lib/html-artifacts.ts src/lib/html-artifacts.test.ts
git commit -m "feat: parse isolated html artifacts"
```

### Task 2: Add preview actions to HTML code blocks

**Interfaces:**
- Consumes: `HtmlArtifact` and `extractHtmlArtifacts` from Task 1.
- Produces: optional `onPreviewArtifact(artifact)` callback on `ChatMarkdown` and a Preview/Reopen button for eligible code blocks.

- [ ] **Step 1: Add an artifact callback contract**

Change the component API to:

```ts
interface ChatMarkdownProps {
  text: string;
  streaming?: boolean;
  messageId?: string;
  selectedArtifactId?: string | null;
  onPreviewArtifact?: (artifact: HtmlArtifact) => void;
}
```

Pass a stable HTML block index through the Markdown render and map it to the parser output for that message. Streaming blocks never show Preview because an unclosed or changing block must not open.

- [ ] **Step 2: Render accessible Preview/Reopen controls**

For eligible settled HTML blocks, render a button beside Copy with `PanelRightOpen` and text `Preview`, or `Reopen` when its ID matches `selectedArtifactId`. Clicking calls `onPreviewArtifact` without executing the HTML in the transcript.

- [ ] **Step 3: Pass message identity from chat bubbles**

Keep the streaming bubble unchanged so partial fenced code remains plain highlighted source.

### Task 3: Build the sandboxed side-by-side workspace

**Files:**
- Create: `src/components/ArtifactPanel.tsx`
- Modify: `src/components/ChatView.tsx`
- Modify: `src/styles.css`

**Interfaces:**
- Consumes: `HtmlArtifact` and `buildArtifactDocument` from Task 1.
- Produces: `ArtifactPanel({ artifact, width, onWidthChange, onClose })`.

- [ ] **Step 1: Create the artifact panel toolbar and iframe**

Render an iframe with the exact security boundary:

```tsx
<iframe
  key={`${artifact.id}:${revision}`}
  title={`Preview of ${artifact.id}`}
  sandbox="allow-scripts"
  srcDoc={buildArtifactDocument(artifact.html)}
/>
```

Do not add `allow-same-origin`, `allow-forms`, `allow-popups`, `allow-downloads`, or navigation permissions. Toolbar actions increment `revision`, copy `artifact.html`, download it through a renderer-created Blob URL, and close the panel. Show a `Wifi` indicator titled `External resources may connect to the network`.

- [ ] **Step 2: Add a keyboard-accessible resize divider**

Use a separator with `role="separator"`, `aria-orientation="vertical"`, and `aria-valuenow`. Pointer dragging clamps the panel between 320 px and 70% of the available workspace. Arrow Left/Right changes the width in 24 px steps; Home and End choose the bounds. Persist the width under `openmausbot.artifactWidth`.

- [ ] **Step 3: Add automatic artifact selection**

In `ChatView`, derive artifacts from visible settled bot text messages. Track the selected artifact per thread in component state. When a new artifact ID appears at the end of the visible branch, select it automatically exactly once. Closing records a closed state for that artifact so unrelated rerenders do not reopen it; a later newly generated artifact still opens.

- [ ] **Step 4: Restructure chat as sibling panes**

Wrap the existing `<main>` and `ArtifactPanel` in a `flex h-full min-w-0 flex-1` container. The chat remains the flexible pane; the artifact panel uses the saved pixel width. Keep Settings, Computer, and App Settings overlays at the `App` level unchanged.

- [ ] **Step 5: Add narrow-window behavior**

At widths below 800 px, render the artifact panel as `position: fixed; inset: 0` above the chat with a Back/Close action. The iframe remains mounted only while an artifact is open. Ensure Escape closes the panel and focus returns to the triggering Preview button when available.
